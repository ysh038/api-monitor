# 명세: 문제 요약 (시간대별 요청 차트 교체)

- 작성일: 2026-09-30
- 상태: 확정 (2026-09-30 사용자 확인 — "1단계 ㄱㄱ")

## 목표

이 대시보드는 개발 단계와 B2G 설치 현장에서 "지금 뭐가 안 되는가"를 빨리 찾는 도구다.
그 상황은 트래픽이 적고, 설정 문제(DB 연결, 외부 주소, 방화벽, 인증서, 인증) 하나가 같은 오류를
수십 번 반복시키는 경우가 많다. 기존 "시간대별 요청" 차트(요청 1건 = 막대 1개)는 이 질문에 답하지 못한다.
차트를 두 목록으로 바꾼다.

1. **반복되는 문제** — 최근 실패를 원인별로 묶어 "문제 몇 개"로 보여 준다.
2. **외부 연결 상태** — 보낸 대상 서버마다 마지막 결과와 마지막 성공 시각을 보여 준다.

추세·p95·오류율 집계는 Grafana(백엔드 로그 표준 `260930_LOGGING_FORMAT`)가 맡으므로 여기서 만들지 않는다.
대신 문제를 묶는 기준을 그 로그 표준의 집계 기준(`route` · `httpStatus` · `errorCode`/`rootCauseType`)과 맞춰,
두 도구에서 같은 문제가 같은 단위로 보이게 한다.

## 범위 밖

- 서버·스타터 변경 (`route`·`errorCode`·`rootCauseType` 수집은 2단계). 이번에는 **값이 오면 쓰도록** 받을 자리만 만든다.
- 시간축 차트, 오류율·p95 같은 집계 수치
- Grafana 링크 (2단계)

## 기준 데이터

- 현재 필터 기준으로 불러온 행 중 **항상 최신 100건**으로 계산한다 (2026-09-30 변경). 불러온 행이 100건보다 적으면 그 수만큼.
  목록이 폴링·더 보기로 길어져도 요약은 "지금" 상태를 본다.
- 화면에 `최근 N건 기준` 이라고 밝힌다 (N = min(100, 불러온 행 수)).

## 수용 기준

테스트 종류: **U** = 단위 테스트, **S** = 스토리 테스트.

### P. 반복되는 문제

- [x] P1 (U): 문제로 보는 행은 실패(5xx·응답 없음)와 4xx 다. 2xx·3xx 는 예외가 있어도 문제로 보지 않는다.
- [x] P2 (U): 묶는 기준 — 받은 요청은 `메서드 + 경로 + 상태 + 원인`, 보낸 요청은 `대상 서버 + 상태 + 원인`.
  - 경로는 `route` 가 있으면 그 값, 없으면 실제 경로에서 쿼리를 떼고 숫자·UUID·16자 이상 16진수 조각을 `{id}` 로 바꾼 값 (`/api/v1/orders/3` → `/api/v1/orders/{id}`).
  - 원인은 `errorCode` → `rootCauseType` → 예외 클래스 순으로 있는 값을 쓴다.
- [x] P3 (U): 받은 요청이 실패했고, 불러온 행 중에 그 요청이 보낸 요청 중 실패한 것이 있으면, 원인은 그 보낸 요청(대상 서버)이다. 그 보낸 요청은 따로 문제로 세지 않는다 (한 사고가 두 줄로 나오지 않게). 부모가 없거나 부모가 성공한 보낸 요청의 실패는 따로 센다.
- [x] P4 (U): 문제마다 제목(상세의 원인 문장과 같은 문장), 맥락(`METHOD 경로` 또는 `→ 대상 서버`), 건수, 마지막 발생 시각, 상태 톤, 가장 최근 행 id 를 가진다.
- [x] P5 (U): 마지막 발생이 최근인 문제부터, 같으면 건수가 많은 순.
- [x] P6 (S): 최대 5개를 보여 주고 더 있으면 머리에 `외 N개` 를 쓴다. 줄을 누르면 그 문제의 가장 최근 요청 상세가 열린다(`onSelect`).
- [x] P7 (S): 문제가 없으면 `최근 요청에서 문제가 없어요` 를 보여 준다.

### H. 외부 연결 상태

- [x] H1 (U): 보낸 요청의 대상 서버마다 호출 수, 실패 수, 마지막 결과(정상 / 4xx / 실패), 마지막 결과 설명, 마지막 성공 시각(없으면 없음), 가장 최근 행 id 를 가진다.
- [x] H2 (U): 마지막 결과 설명 — 정상이면 걸린 시간(`450ms`), 실패면 이유: 타임아웃(`…TimeoutException`, 메시지 `timed out`), 연결 거부(`ConnectException`, `connection refused`), 주소를 찾지 못함(`UnknownHostException`), 인증서 오류(`SSL…Exception`, `CertPathValidatorException`), 그 밖에는 `HTTP 503` 또는 `응답 없음`.
- [x] H3 (U): 마지막 결과가 실패인 서버, 4xx 인 서버, 정상인 서버 순. 같으면 서버 이름 순.
- [x] H4 (S): 최대 5개, 더 있으면 `외 N개`. 줄을 누르면 그 서버로 보낸 가장 최근 요청 상세가 열린다. 보낸 요청이 없으면 `보낸 요청이 없어요`.

### L. 배치

- [x] L1 (S): 두 목록은 요청 기록 카드에서 시간대별 요청 차트 자리에 나란히(좁은 화면에서는 위아래로) 놓인다. 머리에 `최근 N건 기준` (N = min(100, 불러온 행 수)). 불러온 행이 100건을 넘어도 최신 100건만으로 계산한다.
- [x] L2 (S): 목록 칸 높이는 항목 수(0~5)와 관계없이 같다 — 폴링으로 문제가 늘고 줄어도 아래 표가 움직이지 않는다 (dashboard-stable-layout 의 원칙).
- [x] L3 (U): 목록 API 행의 선택 필드 `route`, `error_code`, `root_cause_type` 을 읽는다. 없으면 null (지금 서버·스타터는 보내지 않는다).
