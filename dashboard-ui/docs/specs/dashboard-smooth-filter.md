# 명세: 필터를 바꿀 때 화면이 비지 않게

- 작성일: 2026-09-29
- 상태: 구현됨

## 목표

필터(전체/들어온 요청/외부 호출, 상태 칩, 예외만, 서비스, 검색, 요약 카드)를 바꿀 때마다 요청 기록 표가 **0행 → "불러오는 중이에요…" → 새 결과** 순서로 다시 그려진다. 요약·표 높이가 출렁여서 페이지 전체가 새로고침된 것처럼 보인다.

원인은 목록 무한 쿼리가 필터마다 새 캐시 키로 시작하면서 이전 결과 없이 빈 상태부터 그리기 때문이다(`gcTime: 0`). 실제 페이지 이동은 없다. 주소의 `#/?...`는 필터를 담는 의도된 동작이다.

## 범위 밖

- 주소 해시에 필터를 담는 방식 변경 (새로고침·공유 시 필터 유지에 필요)
- 첫 진입 시의 "불러오는 중" 표시 (보여 줄 이전 결과가 없다)
- 상세 패널 로딩

## 수용 기준

- [x] S1: 필터를 바꾸면 새 결과가 올 때까지 **이전 결과가 그대로** 보이고, 표가 0행이 되거나 "불러오는 중이에요…"·"조건에 맞는 로그가 없습니다."가 나오지 않는다.
- [x] S2: 새 결과를 기다리는 동안 목록은 `isUpdating`이고, 표는 `aria-busy="true"`와 표 위의 얇은 진행 막대(`progressbar`)로 갱신 중임을 알린다. 행을 흐리게 하지 않는다(글자 대비 AA 유지).
- [x] S3: 새 결과가 오면 새 결과로 바뀌고 `isUpdating`이 풀린다.
- [x] S4: 갱신 중에는 "더 보기"를 누를 수 없다 (이전 필터의 다음 페이지를 받는 일 방지).
- [x] S5: 처음 화면을 열 때(이전 결과 없음)는 지금처럼 "불러오는 중이에요…"가 나온다.

## 영향 범위

- 만질 파일: `src/queries/Logs/useLogFeedQuery.ts`, `src/hooks/dashboard/useDashboard.ts`, `src/components/Logs/LogTable/`, `src/pages/DashboardPage.tsx`
- 새 의존성: 없음 (TanStack Query `keepPreviousData`)
- 기존 기능 영향: 폴링(`pollNewer`)은 새 필터의 결과가 도착한 뒤부터 동작한다 (갱신 중에는 새 키의 캐시가 없어 건너뛴다. 기존과 같음).
