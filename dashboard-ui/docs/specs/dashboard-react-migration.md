# 명세: 대시보드 React 이전 + 참고 이미지 기능 추가

- 작성일: 2026-09-29
- 상태: 구현됨 (2026-09-29)

## 목표

`server/public/` 의 바닐라 JS 대시보드는 한 파일에서 문자열로 HTML을 조립해서 기능을 더하기 어렵고,
목록만 봐서는 "무엇이 왜 실패했는지"를 사람이 직접 추적해야 한다. 이 작업은 대시보드를
React(dashboard-ui)로 **기능 그대로** 옮기면서, 참고 이미지가 제안한 진단 기능
(실패 요약, 외부 서버별 실패, 호출 트리, 원인 문장과 확인 가이드, 호출 흐름)을 더해
실패 원인을 화면이 먼저 짚어 주게 한다.

기준 문서: `MIGRATION.md` (이전 완료 후 삭제, API 형식·배포 제약은 `docs/api.md`로 옮김).

## 참고 이미지 분석 (2026-09-29 채팅 첨부)

| 영역 | 이미지에 있는 것 | 기존 화면 대비 |
|------|------------------|----------------|
| 상단 바 | 로고, `개발 모드 · Mock 데이터` 배지, `HH:mm:ss에 새로고침했어요`, 스위치 `5초마다 새로고침`, `Mock 데이터 넣기`/`지우기` | 문구·스위치 모양 변경 |
| 요약 | `요청 38건 중 10건이 실패했어요` / `실패한 10건 중 8건은 외부 서버 호출과 관련 있어요. 서버를 눌러 좁혀 볼 수 있어요.` / 호스트 카드 `ai-server:8000 · 6건 중 2건 실패했어요` | **신규** |
| 요청 기록 카드 | 제목, `38건 보는 중 · 전체 38건`, 스위치 `성공한 요청 묶어 보기` | **신규** (건수, 묶기) |
| 필터 | 세그먼트, 색 점이 있는 상태 칩, `예외가 난 요청만`, 검색 `경로, 예외, requestId로 찾기` | 모양 변경 |
| 시간대별 요청 | 요청 하나당 막대 하나, 높이 = 심각도(2xx 낮은 회색 / 4xx 주황 / 5xx·응답 없음 높은 빨강), 5분 눈금 | **신규** |
| 표 | 상태(색 글자), 메서드, 경로, 걸린 시간(막대+값), 시각(ms 흐리게), 예외 | 소요 막대 **신규** |
| 표 — 호출 트리 | 외부 호출이 부모 요청 바로 아래 `└ → host/path` 로 들여써짐 | **신규** |
| 표 — 묶음 | 연속된 정상 요청을 `✓ 2xx · 정상 처리한 요청 N건 · 경로들 · 시작–끝 시각 · 펼치기` 한 줄로 | **신규** |
| 표 — 공백 | `15분 25초 동안 들어온 요청이 없어요` 구분 줄 | **신규** |
| 표 — 강조 | 실패(5xx·응답 없음) 행은 옅은 빨강 배경, 선택 행은 파랑 배경 | 모양 변경 |
| 상세 | `500 · 서버 오류` 배지, 원인 문장(`pg-gateway:9000 호출이 실패해서 이 요청도 실패했어요`), `METHOD path`, `이렇게 확인해 보세요` 번호 목록, 상태·방향·시각(`9월 29일 오전 09:08:46.227`)·걸린 시간·예외 표, 예외 박스, `호출 흐름` 워터폴(0 · 중간 · 끝 눈금) | 진단·가이드·흐름 **신규** |

이미지처럼 **사이드바는 없앤다** (사용자 결정). 서비스 필터는 필터 줄의 선택 상자로, 외부 호출 대상
필터는 요약의 호스트 카드로 옮긴다. 그 밖에 이미지에 없는 기존 기능(서비스 컬럼, 더 보기, requestId 복사,
cause 체인, 스택트레이스, 연관 목록, 요청/응답 탭, MOCK 태그 등)은 **그대로 유지**한다.

## 용어

- **실패**: `status_code` 가 5xx 이거나 `null`(응답 없음). 서버 `api/services` 의 `errors` 와 같은 정의.
- **받은 요청 / 보낸 요청** (화면 문구, 2026-09-30): `INBOUND` = 우리 서비스가 받은 요청, `OUTBOUND` = 우리 서비스가 다른 서버로 보낸 요청. 이전 문구 "들어온 요청 / 외부 호출"은 기준(방향·대상)이 섞여 있어 바꿨다.
- **거부**: `status_code` 가 4xx. 실패로 세지 않지만 정상도 아니므로 요약에서 따로 알린다 (2026-09-29 피드백).
- **정상**: 2xx·3xx 이고 예외가 없으며, 트리로 붙은 외부 호출도 모두 정상.
- **불러온 행**: 현재 필터로 받아 화면에 가진 행(첫 100건 + 폴링 + 더 보기).

테스트 종류: **U** = Vitest 단위 테스트(순수 함수), **S** = Storybook 스토리 play 테스트.

### A. 배포 제약

- [x] A1 (U): 목록 요청 URL은 `api/logs?...` 형태로 `/` 로 시작하지 않는다 (상세·services·health·dev/mock 도 동일).
- [x] A2 (U): 필터 → 쿼리스트링 변환은 빈 값은 빼고 `kind, status(쉼표), q` 를 넣는다. `service`·`exception`·`host` 는 보내지 않는다 (2026-09-30 해당 필터 제거).
- [x] A3 (빌드 확인): `npm run build` 결과 `dist/index.html` 의 스크립트·CSS 경로가 `./assets/...` 이다.

### B. 표시 형식

- [x] B1 (U): 시각은 오늘이면 `HH:mm:ss.SSS`, 오늘이 아니면 `MM-DD HH:mm:ss.SSS`.
- [x] B2 (U): 걸린 시간은 1000ms 미만 `436ms`, 이상 `3.0초`, 10초 이상 `12초`, 값이 없으면 `-`.
- [x] B3 (U): 상태 분류 — 2xx success, 3xx info, 4xx warning, 5xx danger, `null` 은 danger + 라벨 `응답 없음`.
- [x] B4 (U): 소요 막대 톤 — 3초 이상 danger, 1초 이상 warning, 그 외 neutral. 길이는 0~1 로그 스케일(3초 = 1).
- [x] B5 (U): 예외 톤 — 상태가 4xx 이하로 처리된 예외는 warning, 5xx·응답 없음은 danger.
- [x] B6 (U): 상세 시각은 `9월 29일 오전 09:08:46.227` 형식.
- [x] B7 (U): 상태 문구 — `500 Internal Server Error`, `404 Not Found` 등 표준 사유, 모르는 코드는 숫자만, `null` 은 `응답 없음`.

### C. 목록 구성 (트리·묶음)

- [x] C1 (U): 외부 호출의 `parent_request_id` 와 같은 `request_id` 를 가진 받은 요청이 불러온 행에 있으면, 그 외부 호출은 부모 바로 아래 자식으로 붙는다. 부모가 없으면 최상위에 남는다.
- [x] C2 (U): 묶기가 켜져 있으면 **연속된 정상 최상위 항목 2개 이상**이 하나의 묶음이 된다. 묶음은 묶인 행들만 가진다 (경로 목록·시각 범위는 2026-09-30 화면에서 빼면서 함께 제거). 1개뿐이면 묶지 않는다.
- [x] C3 (U): 묶기가 꺼져 있으면 묶음이 없다.
- ~~C4: 5분 이상 비면 공백 줄(`15분 25초 동안 …`)~~ — 2026-09-30 제거 (필요 없다는 요청). 공백이 정상 요청 묶음을 끊던 동작도 함께 없앴다 — 끊는 이유가 화면에 안 보이면 같은 묶음 줄 두 개가 나란히 나와 헷갈린다. 묶음 줄에는 시작–끝 시각이 이미 보인다.
- [x] C5 (S): 묶음 줄은 표의 한 행처럼 보인다 (2026-09-30) — 일반 행과 같은 칸(7칸)·같은 흰 배경에, 상태 칸 `› 2xx`, 서비스 칸은 묶인 행이 모두 같은 서비스면 그 이름, 경로 칸 `정상 처리한 요청 N건`, 나머지 칸은 비운다. 경로·시각 범위는 없다. 흐린 글씨와 아래 얇은 선 한 겹으로 접힌 여러 줄임을 표시한다. 행 어디를 눌러도(또는 상태 칸 버튼에서 Enter/Space) 펼쳐지고 `aria-expanded` 가 바뀐다. 펼치면 화살표가 아래로 돌고 `접기` 가 보이며, 묶였던 행들은 왼쪽 세로선(`data-grouped`)으로 표시한다.
- [x] C5a (S): 묶음을 여닫을 때 아코디언처럼 움직인다 (2026-09-30). 펼치면 묶였던 행들이 높이 0에서 원래 높이로 늘어나고, 접으면 원래 높이에서 0으로 줄어든 뒤 사라진다. 아래 행들은 미리 점프하지 않고 그 속도에 맞춰 함께 밀리고 당겨진다 — 행의 여백·테두리까지 같은 전환 안에 넣는다. 전환 시간은 `--duration-slow`(320ms), `prefers-reduced-motion` 이면 즉시.
- [x] C5b (U+S): 아코디언이 끊기지 않게 (2026-09-30) — ① 묶음을 여닫아도 묶음 밖 행은 다시 렌더링하지 않는다(행 메모이즈) ② 펼침은 행이 나타난 첫 프레임부터 움직인다(프레임 대기 없음), 접는 도중 다시 펼치면 그 높이에서 이어서 늘어난다 ③ 표에 그릴 행(보낸 요청 포함)이 30개를 넘는 묶음은 애니메이션 없이 바로 여닫는다.
- [x] C6 (S): 외부 호출 행은 `→ host path` 로, 부모 없는 외부 호출은 `백그라운드` 태그, 자식이 트리에 안 보이는 받은 요청은 `보낸 요청 N` 태그를 보인다.
- [x] C7 (S): `is_mock` 행에는 `MOCK` 태그가 보인다.
- [x] C8 (S): 빈 목록 문구 — 필터가 없으면 `아직 수신된 로그가 없습니다.`, 있으면 `조건에 맞는 로그가 없습니다.`
- [x] C9 (S): 불러온 개수가 페이지 크기(100) 이상이면 `더 보기` 버튼이 보이고 누르면 `onLoadMore` 가 호출된다.
- [x] C10 (S): 행을 클릭하거나 Enter 로 선택하면 `onSelect(id)` 가 호출된다.

### E. 필터

- [x] E1 (S): 세그먼트 `전체 / 받은 요청 / 보낸 요청` 중 선택된 것이 `aria-pressed`(또는 `aria-checked`) true.
- [x] E2 (S): 상태 칩 2xx·4xx·5xx·응답 없음은 여러 개 동시 선택되고 각각 `aria-pressed` 가 토글된다.
- [x] E2a (S): 상태 칩 4개는 한 묶음으로 보인다 — 세그먼트(`전체 · 받은 요청 · 보낸 요청`)와 같은 회색 트랙 한 장 위에 놓이고, 꺼진 칩은 자기 배경이 없다(투명). 켜진 칩만 상태 색 배경을 가진다 (2026-09-30).
- [x] E3 (U): 검색 입력은 300ms 디바운스 후 한 번만 반영된다 (`useDebouncedValue`).
- [x] E4 (U): 필터 상태 전이 — 구분(kind)은 값만 바뀌고, 상태 칩은 여러 개를 켜고 끌 수 있으며 순서는 `2xx, 4xx, 5xx, none` 으로 고정된다.
- [x] E5 (U): 필터는 URL 해시(`#/?kind=..&status=..&q=..`)와 양방향으로 변환된다 (새로고침·공유 가능, 라우터는 해시 방식만). 예전 링크의 `service`·`exception`·`host` 값은 읽지 않는다 — 화면에 없는 필터가 몰래 걸리지 않게.

### F. 상세

- [x] F1 (U): 원인 문장 — 실패한 자식이 있는 실패 요청은 `{host} 호출이 실패해서 이 요청도 실패했어요`, 응답 없는 외부 호출은 `{host}에서 응답을 받지 못했어요`, 5xx 외부 호출은 `{host}에서 {code} 오류가 났어요`, 예외 있는 5xx 는 `서버 안에서 {Class} 예외가 났어요`, 예외 있는 4xx 는 `앱이 {Class} 예외를 {code} 응답으로 처리했어요`, 예외 없는 4xx 는 `{code} 응답으로 요청을 거부했어요`, 예외 없는 5xx 는 `서버가 {code} 오류를 돌려줬어요`, 정상은 `정상 처리했어요`.
- [x] F2 (U): (호스트 뒤 조사 오류를 피하려고 `{host} 서버가` 로 쓴다) 확인 가이드 — 타임아웃 계열 예외(`SocketTimeoutException`, 메시지에 `timed out`)면 `{host} 서버가 정상적으로 떠 있는지` + `읽기 타임아웃 {걸린 시간}가 충분한지`, 연결 실패(`ConnectException`, `Connection refused`)면 대상 주소·포트, 401/403 은 인증 정보, 404 는 경로, 검증 예외(`MethodArgumentNotValidException`, 400)는 요청 값, `DataIntegrityViolationException` 은 제약 조건, 외부 5xx 는 대상 서버 로그. 해당 없으면 빈 목록(섹션 숨김).
- [x] F2a (U): 확인 가이드 규칙 추가 (2026-09-30). 예외 클래스로 알 수 있는 경우를 상태 코드 규칙보다 먼저 본다.
  - DB 커넥션 부족(`CannotGetJdbcConnectionException`, `SQLTransientConnectionException`, 메시지 `Connection is not available`) → 커넥션 풀 크기·오래 걸리는 쿼리 (타임아웃 규칙보다 먼저)
  - SSL(`SSLHandshakeException`, `SSLException`, `CertPathValidatorException`) → `{host} 서버 인증서`
  - 동시 수정 충돌(`OptimisticLockException`, `ObjectOptimisticLockingFailureException`, 409) → 같은 데이터를 동시에 고친 요청
  - `NullPointerException` → 스택트레이스의 강조된 앱 코드 줄에서 비어 있을 수 있는 값

  - `OutOfMemoryError`, `StackOverflowError` → 메모리 사용량·끝없는 재귀
  - JSON 읽기 실패(`HttpMessageNotReadableException`) → 요청 바디 JSON 형식·필드 타입 (검증 실패 규칙에서 분리)

  - 405·`HttpRequestMethodNotSupportedException` → HTTP 메서드, 415·`HttpMediaTypeNotSupportedException` → `Content-Type`, 413·`MaxUploadSizeExceededException` → 업로드 크기 제한, 429 → 호출 횟수 제한(보낸 요청이면 `{host}`의 제한)
